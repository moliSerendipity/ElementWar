# ElementWar 开发路由

先遵守根 `AGENTS.md`；只有 Full 读取 `Docs/Workflow.md`。

## 流程等级

| 等级     | 条件                                                         | 默认动作                                                     |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| Fast     | 需求明确、沿用现有契约、无高影响边界                         | 用户请求即授权；读直接代码/调用者/测试；不建 Spec/ADR        |
| Standard | 跨现有系统，但所有权、公共契约和序列化边界已确定             | 用户请求即授权；再读一个相关架构页；默认不建 Spec/ADR        |
| Full     | 状态所有者、跨模块契约、asmdef、序列化/scene/prefab、Legacy、发布级性能/兼容性，或多个方案会明显改变行为/接口/验收 | 读 `Docs/Workflow.md`；只对未决高影响选择确认；按需建 Spec/ADR |

跨文件、新功能和文件数量不决定等级。实施中首次触发 Full 条件时再升级，不因未来可能复杂提前升级。

## 上下文预算

1. 先搜索符号，再读定义、直接调用者和最相关测试；首次只扩展一层依赖。
2. 长文档按 heading 区间读取，不为单个任务全文 `cat` Roadmap/Design/Feature/ADR。
3. 同一会话已读取且未变化的文件不重复全文读取；复核只看变化区间或 scoped diff。
4. `继续下一阶段` 只读 `DevelopmentRoadmap.md` 的“当前唯一下一项”，再读取路线文件中该 `### 任务` 到下一任务前的区块。
5. 历史 Feature/ADR 默认不读；当前架构/任务明确需要某项长期决策时，只读对应段落。
6. Git diff 默认限制到当前修改文件；设计、验证、性能资料都按实际需要加载，不做保险式扩张。

## 复杂度门槛

默认选择满足当前可观察验收的最直接实现。Request/Result/RejectionReason、新 Event、缓存/字典、平行状态、Target/Lifecycle ID、去重集合、生命周期包装、策略/工厂/通用接口都**不是默认模板**。

新增上述构件必须至少满足一项：当前消费者需要；当前合法路径存在具体失败；任务明确要求；现在不做会造成已确定的 API/序列化迁移或重复实现。Roadmap、未来可能需求、其他组件已有结构或“更健壮”不能单独作为依据。

上游已经保证且之后不会变化的不变量，不在热路径重复校验；当前没有对象池/异步/重连/复用路径时，不设计对应防线。详细代码注释按 `Docs/CodingStandards.md` 保留，不视为设计复杂度。

## 执行

1. **定位**：确认入口、权威所有者、直接消费者和相关测试；仓库能回答的内容自行确认。
2. **实现**：完成一个最小可观察行为链，不顺手扩范围、清理旧架构或预埋未来框架。
3. **验证**：从最相关、最低成本的现有入口开始；只有目标证据等级需要时才递进。
4. **收口**：检查 scoped diff，只同步受影响的当前事实、任务状态和证据；最终报告只写实际修改、验证结果、未运行项和真实剩余风险。
