# ElementWar 功能工作流

完整遵守项目根 `AGENTS.md` 和 `Docs/Workflow.md`；本 Skill 只定义上下文路由与执行顺序，不复制两者的规则正文。

## 按需加载

1. 始终读取 `AGENTS.md`、`Docs/Workflow.md`、相关实现和测试、Git 状态及 scoped diff。
2. 用户说“继续下一阶段”、询问顺序或未指定功能时，读取 `Docs/DevelopmentRoadmap.md` 中唯一 `Next` 及其一份路线细则；指定功能时只核对该任务及依赖。
3. 涉及程序集、状态所有权、序列化、scene/prefab、旧架构或迁移时读取 `Docs/Architecture.md`；修改 C# 时读取 `Docs/CodingStandards.md`。
4. 设计或执行测试、构建、性能检查时读取 `references/verification-matrix.md`。
5. 玩家可见玩法先用 `Docs/GameDesign.md` 定位，再按需读取 `Design/Combat.md`、`Elements.md`、`Run.md` 或 `Networking.md` 中直接相关的少量细则。

不要预加载全部设计、路线、历史 Feature Spec 或 ADR。候选包中的文件只视为提案，不能当作当前工程事实。

## 执行顺序

### 1. 建立事实

- 确认实际入口、调用链、状态所有者、生命周期、配置/请求/运行时不变量及其唯一校验层。
- 核对 asmdef、序列化引用、当前验证入口和用户未提交改动；区分已验证事实、推断、待决定项与过期文档。
- 用户质疑既有实现时，先按 `Docs/Workflow.md` 对范围内构件给出保留、修改、替换、删除或暂缓结论；完成前不在旧结构上叠加方案。
- 仓库能回答的内容自行确认，只集中询问高影响选择。

### 2. 契约与授权

- 按 `Docs/Workflow.md` 在对话中给出精简契约和当前最小实现/最低成本稳定接缝比较。
- 请求授权前逐项核对“用户明确问题 → 可观察验收”和“新增或复用构件 → 必要性判断”；任一缺失不得打包请求授权。
- 授权前不编辑或创建 Feature Spec；获得明确授权后，才按 `Docs/Features/TEMPLATE.md` 创建或更新适用的 Spec。用户明确限制文档范围时遵守该限制。
- 实时仓库与已批准契约冲突，或出现新的公共 API、序列化、状态所有权、迁移、行为或验收选择时暂停并重新确认。

### 3. 实施切片

- 一次完成一个最小、可观察、可验证的行为链，只修改获批范围并复用权威事实源。
- 处理适用的初始化、启用/禁用、订阅、死亡、重置和对象池复用；每项不变量只由其权威层校验，跨层防御必须对应真实的新失败来源。
- 新增或重写 Component 时按当前任务重新核对状态、入口、消费者和生命周期，不套用其他 Component 模板；简单状态组件若开始聚合身份、跨组件策略、请求包装、去重、时间线或事件事务，按 `Docs/Workflow.md` 先复核边界和必要性。
- 不静默增加脚本、公共类型、配置资产、缓存、状态或可配置分支；超出获批复杂度边界时先比较更小方案并重新授权。
- 每个切片后检查 scoped diff，不做无关清理、广泛格式化或旧架构扩展。

### 4. 验证与审查

- 从最低成本的精确检查开始，按验证矩阵和目标证据等级递进；保存 XML、日志、Player、截图/录像或 Profiler 原始证据。
- 审查重复校验、平行状态、生命周期、公共/序列化边界和完成声明；测试应证明可观察行为而非绑定内部实现，独立审查按风险决定，不固定拆任务。
- 将发现分为已确认缺陷、违反验收、证据缺口和可选增强；前两类阻断，证据缺口下调声明或补证据，可选增强不扩大当前范围。

### 5. 收口

- 按 `Docs/Workflow.md` 报告实际修改、命令、数量、结果、证据、未运行项、风险、回滚和文档同步。
- 路线功能同步任务状态、证据、解锁项和新的唯一 `Next`；不得用代码检查或旧日志冒充运行时证据。
