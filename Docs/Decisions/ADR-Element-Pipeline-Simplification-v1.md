# ADR：元素施加与反应管线精简 v1

- 状态：Accepted
- 日期：2026-08-23
- 修订日期：2026-08-27（仅同步通用扩展门槛，不改变元素运行时契约）
- 关联 Feature 记录：[`ElementPipelineSimplificationV1.md`](../Features/ElementPipelineSimplificationV1.md)
- 修订关系：修订 ELM-010/020 ADR 的实现形状，并取代 [`ADR-Element-Reaction-Pipeline-v1.md`](ADR-Element-Reaction-Pipeline-v1.md) 中关于反应表资产、批次包装请求和结果拒绝矩阵的决策。

## Context

ELM-010～030 的玩法行为已经成立，但实现为了假设中的多槽、运行时换表、派生来源、基准伤害和详细诊断提前增加了配置资产、包装请求、组合键、多个结果快照和拒绝枚举。部分配置结构还在 Bootstrap 与运行时重复校验。这些抽象没有当前生产消费者，却让一次简单反应需要跨越过多脚本和重复判断。

## Decision

选择方案 B，并保留必要职责边界：来源快照改为不可变 class；请求和应用结果保持小型 readonly struct；目标 Runtime 只拥有单槽、以 SourceId 为键的间隔、版本和执行去重；反应管线提供一/二请求重载并内置首版六对固定映射；反应结果只描述已成功提交的反应。

配置合法性由 `ConfigBase.Validate` 在 Bootstrap 初始化阶段统一保证。运行时只检查可能随请求或生命周期变化的引用、身份、时间、当前附着、间隔与执行去重，以及时间加法是否能形成有限结果；不得重新枚举验证已冻结配置字段。

## Rationale
- 可读性：一次元素施加或反应应能沿来源、请求、目标状态、反应结果一条路径理解。
- 单一事实源：目标身份不复制进目标自有字典键；请求不复制进调用方已经持有的结果；配置结构不在 Bootstrap 与热路径重复验证。
- 当前需求：首版只有四元素六个固定组合、一个主要槽和弹药/技能两个有序阶段，没有运行时换表或设计师编辑映射需求。
- 安全边界：生命周期、来源间隔、执行去重和版本匹配仍必须由目标 Runtime 原子裁决，不能为减少类型而削弱状态安全。
- 演进成本：未来出现真实第五元素、多槽、运行时换表或第三处理阶段时，可以基于消费者重新设计，而不是现在预付复杂度。

## Constraints

- 新增类型、字段、配置或缓存必须由当前消费者、当前合法路径或已确定迁移成本证明。Roadmap 和未来可能需求不能单独证明新增复杂度合理；当前没有消费者或真实失败路径时默认不预建。
- 同一事实只允许一个验证所有者。调用层只验证跨请求关系，目标 Runtime 验证可变目标状态，Bootstrap 验证配置结构。
- 结果只携带调用方无法从已有输入或权威状态获得的事实；不为日志便利复制完整请求、前后相同快照或处理计数。
- 当前只有一个槽时不暴露集合 API；只有固定六对时不创建可编辑资产；只有两个固定阶段时不创建可空批次容器。
- 测试优先断言状态、事件和结果行为；不得用反射锁定反应提交内部步骤，除非存在无法通过公开行为覆盖的已批准风险。
- 扩展必须指出当前具体行为、真实失败路径或确定迁移成本，以及更小方案为何不足；只有长期架构决策才更新 ADR，Feature Spec 仅在 Full 或需要长期契约记录时建立。

## Consequences
- 删除反应表配置/资产、批次包装请求、复合间隔键和多个公共查询/消费入口。
- 元素生产链更短，默认/空状态更自然，重复校验和双层循环消失。
- 原子消费、版本安全、来源间隔、执行去重和目标复用行为保持不变。
- 反应映射变化现在是代码变化，需要测试和版本审查；这与首版固定规则一致。
- 普通应用拒绝不会通过 `ElementReactionResult` 复制一套详细矩阵；需要诊断时读取目标侧日志/测试或在真实消费者出现后设计窄事件。
- 派生反应不递归附着由未来输出生产者遵守，当前管线不再携带一个没有真实派生调用者的 Origin 字段。

## Revisit When

出现以下任一真实需求时重新评估，而不是提前恢复全部旧设计：第五种可组合元素、设计师需要无代码改映射、多个活动反应规则集、同一命中超过两个有序元素阶段、目标同时维护多个主要附着、或生产诊断消费者确实需要结构化拒绝结果。

> 旧备选方案展开、迁移步骤、验证流水账和回滚过程由 Git 历史追溯；当前开发只依赖本页决定、活动 Architecture/Design 与代码。
