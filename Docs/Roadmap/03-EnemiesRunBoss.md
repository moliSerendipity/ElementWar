# 路线 03：敌人、Run 与 Boss

- 上级路线：[`DevelopmentRoadmap.md`](../DevelopmentRoadmap.md)
- 目标设计：[`Run.md`](../Design/Run.md)、[`Combat.md`](../Design/Combat.md)、[`Elements.md`](../Design/Elements.md)
- 当前架构：[`Architecture.md`](../Architecture.md)
- 维护日期：2026-08-11

敌人路线先用生产行为特征测试建立安全网，再决定局部加固或边界重构；不会预先承诺整套重写。Run 路线从唯一状态所有者开始，逐步接入波次、恢复、强化、失败与重开，最后用 Boss 和完整一次游玩收口。

## M09 现有敌人链加固

### ENM-010 当前敌人生产行为特征测试与审计门

- 状态：Ready
- 依赖：`CMB-010`。
- 当前缺口：现有 EnemyBrain/StateMachine/Locomotion/Attack 已可运行，但缺少足够生产特征证据；直接重构无法区分历史行为、缺陷和设计变化。
- 实施要点：① 从 Bootstrap 追踪生成、选目标、追击、攻击、受伤、死亡和禁用链；② 测试状态转换、攻击帧、多 Collider、目标丢失、NavMesh 失败和事件释放；③ 记录与设计不一致项；④ 按“保留/局部修补/边界重构”分类；⑤ 只有测试证明边界妨碍后续任务才批准重写。
- 可观察完成：当前敌人行为有可重复的特征测试和差异清单，后续每次修改能说明是兼容还是有意改变。
- 范围：只读审计与测试优先；发现生产缺陷若超出批准范围则另行授权。
- 验证：新增测试自身失败探针、EditMode/PlayMode、scoped diff 审阅。
- 解锁：`ENM-020`、`ENM-030`、`ENM-040`。

### ENM-020 敌人目标身份、威胁与锁定

- 状态：Planned
- 依赖：`ENM-010`、`PTY-010`。
- 当前缺口：敌人以 Transform 为主要目标，无法稳定表达双角色阵营、倒地过滤、威胁、锁定保持和切换后的重新选择。
- 实施要点：① 只从合法 Combatant 选择；② 组合当前主控基础威胁、距离与近期伤害并使用稳定 tie-break；③ 普通敌人/Boss 偏好可配置；④ 设置最短锁定，攻击进入出手后不换目标；⑤ Downed/死亡/禁用/不可达按批准时点失效；⑥ AI 决策不依赖 Presentation 或标签搜索。
- 可观察完成：双角色快速切换、倒地和复活时敌人始终有确定合法目标，不在两目标间每帧抖动。
- 范围：Enemy 决策与目标服务；非目标是复杂仇恨 UI 或网络同步。
- 验证：选择矩阵 EditMode，多角色/NavMesh PlayMode。
- 解锁：`AI-020`、`ENM-050`～`ENM-070`。

### ENM-030 攻击生命周期与一次命中语义

- 状态：Planned
- 依赖：`ENM-010`、`CMB-010`。
- 当前缺口：攻击重叠查询可能按 Collider 处理，且帧跳跃、动画回调、禁用和目标离开可能导致漏击或重复提交。
- 实施要点：① 定义 Windup/Active/Recovery/Cancel；② 每次攻击创建唯一执行身份；③ Active 窗口对权威目标去重；④ 低帧率跨越窗口仍按批准规则结算；⑤ 死亡/硬直/禁用取消，迟到回调无效。
- 可观察完成：一次挥击对同一角色最多一次伤害，两个不同合法目标可各一次；取消和帧跳不会重复或永久卡状态。
- 范围：EnemyAttack/状态机/动画适配；物理和计时风险高。
- 验证：边界时刻 EditMode、低帧率/多 Collider PlayMode、独立审查。
- 解锁：`ENM-050`～`ENM-070`、Boss 攻击切片。

### ENM-040 敌人死亡、禁用与池化重置

- 状态：Planned
- 依赖：`ENM-010`、`ENM-030`。
- 当前缺口：生命耗尽已统一，但目标、NavMesh、攻击回调、控制/附着、事件订阅和波次计数还没有完整 reuse 契约。
- 实施要点：① 列出所有可变运行时状态；② 死亡只提交一次并停止决策/伤害；③ OnReturn 清理计时器、订阅、目标、速度、附着、Modifier 和攻击执行；④ OnRent 按配置重建；⑤ Run 只消费已提交的 Spawned/Defeated 事实。
- 可观察完成：同一敌人实例反复租借与击杀，第二次行为与新实例一致，不产生幽灵攻击或重复死亡计数。
- 范围：Enemy 生命周期、对象池适配和事件；非目标是波次编排。
- 验证：复用循环 PlayMode、事件计数与内存订阅检查。
- 解锁：`RUN-030`、`PERF-010`。

## M10 敌人代表性切片

### ENM-050 近战基础敌人与数据驱动调参

- 状态：Planned
- 依赖：`ENM-020`、`ENM-030`、`ENM-040`。
- 当前缺口：现有近战行为需收敛为主线可配置 prefab，攻击/移动/韧性/反馈资产需通过真实消费者校验。
- 实施要点：迁移到稳定配置 ID；明确追击/攻击距离；接入韧性、元素和死亡；完成预警/命中/受击反馈；保留一套权威 prefab。
- 可观察完成：近战敌人从生成到死亡可重复运行并被元素/控制正确影响。
- 验证：配置校验、PlayMode、主线人工战斗。
- 解锁：`LVL-010`、`RUN-030`。

### ENM-060 远程敌人垂直切片

- 状态：Planned
- 依赖：`ENM-020`、`ENM-030`、`PRJ-010`。
- 当前缺口：没有使用统一投射物/攻击身份的远程敌人和射线/弹道预警。
- 实施要点：建立保持距离/射击决策；发射时冻结敌人来源；处理 LOS/枪口遮挡/目标失效；预警与实际时点一致；死亡后在途弹按批准规则保留或失效。
- 可观察完成：远程敌人只攻击合法角色，投射物归因正确且有可读规避窗口。
- 验证：决策 EditMode、投射物/低帧率 PlayMode、人工可读性。
- 解锁：多类型波次、Boss 远程攻击。

### ENM-070 重型精英、韧性与控制抵抗

- 状态：Planned
- 依赖：`ENM-020`、`ENM-030`、`CMB-030`、`ELM-080`。
- 当前缺口：没有验证普通敌人和 Boss 之间的控制抵抗、韧性窗口和重攻击威胁层级。
- 实施要点：基于同一敌人边界组合高韧性/慢攻击；控制转换为韧性伤害或缩短；失衡有明确窗口；弱点/反馈可读；不复制独立伤害链。
- 可观察完成：精英可被玩家策略性打出失衡，但不能被普通控制永久锁死。
- 验证：抗性/阈值 EditMode、组合反应 PlayMode、人工难度检查。
- 解锁：`BOS-010`、精英波次。

## M11 Arena、Run 与波次

### LVL-010 主线 Arena 灰盒与可验证生成点

- 状态：Planned
- 依赖：`LIC-010`、`ENM-050`。
- 当前缺口：Bootstrap 是当前主线入口，但首版战斗场地、NavMesh 边界、出生/复活/波次生成点和相机安全区尚未形成正式可验证布局。
- 实施要点：先用可分发灰盒资产；定义玩家/敌人/救援/掉落点；烘焙并校验 NavMesh；设置越界恢复；场景对象由组合根显式引用而非名称查找。
- 可观察完成：两角色和代表敌人在场地中无明显卡住/出生重叠，重开可恢复同一基础布局。
- 范围：scene/prefab/NavMesh 序列化迁移，需引用检查和人工验收。非目标是最终美术装修。
- 验证：场景资产校验、NavMesh PlayMode、Bootstrap 人工走查。
- 解锁：`RUN-010`、`RUN-030`。

### LVL-020 研究设施主题、美术、照明与战斗可读性

- 状态：Planned
- 依赖：`LVL-010`、`LIC-010`、`BOS-030`。
- 当前缺口：灰盒能证明导航和生成，但尚未形成废弃元素武器研究设施主题、短入口教学、三方向来敌、远程高处、手雷弹跳表面和 Boss 安全空间的发布场景。
- 实施要点：① 在不改变灰盒关键尺寸前提下分批替换获准资产；② 保持中心开阔、外围侧路/遮挡与三个可读入口；③ 材质/碰撞支持可预测弹跳；④ 灯光、VFX 和音频不遮蔽敌人预警/元素图标；⑤ 只用一句引导文案，不新增 NPC、对话或过场。
- 可观察完成：场景主题明确，普通波次与 Boss 威胁可读，导航/弹道/相机无因装饰产生的新阻断。
- 范围：scene、prefab、材质、灯光、音频序列化资产；需许可、GUID/引用、性能和人工验收。
- 验证：NavMesh/场景加载 PlayMode、弹道回归、代表性 Profiler、人工视觉/可读性检查。
- 解锁：`RUN-090`、`BUILD-010`。

### RUN-010 RunRuntime 与 StageRuntime 唯一状态机

- 状态：Planned
- 依赖：`ARC-010`、`LIFE-020`、`LVL-010`。
- 当前缺口：现有 Stage/Run 定义多为壳，没有一次游玩的权威状态、当前阶段、暂停/结算/失败和重开边界。
- 实施要点：① 定义 Boot/Preparing/InWave/Intermission/Boss/Success/Failed/Restarting；② Run 持有种子、Party、阶段和共享资源引用；③ Stage 只负责当前内容进度；④ 所有转换有条件、单次事件和非法请求结果；⑤ 组合根创建/销毁，UI 不写状态。
- 可观察完成：调试命令或最小场景可确定地推进合法状态，重复完成/失败事件不会二次转换。
- 范围：状态所有权与场景组合根，需要 ADR。非目标是实际波次、强化内容和结果 UI。
- 验证：完整转换表 EditMode、Bootstrap 生命周期 PlayMode。
- 解锁：`RUN-020`、`RUN-050`、`HUD-030`。

### RUN-020 Stage/Wave 配置与运行时计划

- 状态：Planned
- 依赖：`RUN-010`、`ENM-050`。
- 当前缺口：现有 Stage 定义字段不足以驱动敌人组、延迟、上限、完成条件和可重复种子计划。
- 实施要点：从首批真实波次反推最小 schema；稳定引用敌人配置/生成点；构建时生成只读运行计划；校验空波、非法数量、重复 ID 和不可达点；配置不保存可变进度。
- 可观察完成：同一配置与种子生成同一波次计划，非法资产在进入 Play 前明确失败。
- 范围：Definition 与序列化配置，可能替换现有空壳；需要迁移计划/ADR。
- 验证：配置与种子 EditMode、真实 ScriptableObject 加载。
- 解锁：`RUN-030`。

### RUN-030 波次生成、存活计数与结束门

- 状态：Planned
- 依赖：`RUN-020`、`ENM-040`、`LVL-010`。
- 当前缺口：没有基于权威 Spawned/Defeated 事实的波次计数、并发上限、生成失败处理和阶段结束伤害停机。
- 实施要点：按运行计划生成；只计入成功租借的敌人；死亡/返回只结算一次；生成失败可重试或明确失败；波次/Run 结束停止新生成和迟到攻击；清理剩余实例。
- 可观察完成：显示计数与真实存活敌人一致，最后敌人死亡只完成一次波次，失败/重开无幽灵敌人。
- 验证：计数/失败注入 EditMode，大量生成/重开 PlayMode。
- 解锁：`RUN-035`、`UPG-020`、`PERF-010`。

### RUN-035 第一、第二波敌人编排与调试

- 状态：Planned
- 依赖：`RUN-030`、`ENM-050`、`ENM-060`、`ENM-070`。
- 当前缺口：运行时波次完成后仍需把设计中的教学组合与精英组合落成真实配置，并证明数量、方向、节奏和难度可读。
- 实施要点：① 第一波只用近战+远程并逐步增加同时压力；② 第二波混合两类普通敌人与一名重型精英；③ 从三个方向生成但避免无提示完全包围；④ 每组设并发上限、间隔和完成条件；⑤ 记录首轮调试数据，不宣称最终平衡。
- 可观察完成：第一波教学移动/闪避/远程威胁，第二波突出精英优先级；相同种子可复现且不会因生成失败卡关。
- 范围：Stage/Wave 配置、生成点和反馈；非目标是第三波小怪，第三波只由 Boss 构成。
- 验证：配置/种子 EditMode、完整两波 PlayMode、人工难度与可读性记录。
- 解锁：`RUN-040`、`PERF-010`。

### UPG-010 Typed Upgrade 定义、选择池与确定性抽取

- 状态：Planned
- 依赖：`MOD-010`、`RUN-010`。
- 当前缺口：没有可应用到角色/Party/武器/反应的类型安全强化定义、互斥/前置、权重和种子抽取。
- 实施要点：从九个设计强化归纳最小类型；每个 Upgrade 用稳定 ID；验证目标与参数；按 Run 种子抽取无重复候选；不执行字符串反射或直接改资产。
- 可观察完成：相同种子和已选集合得到相同合法候选，非法组合在加载时拒绝。
- 范围：Definition/Gameplay 公共契约，需要 ADR；非目标是九个内容一次完成。
- 验证：抽取/约束/配置 EditMode。
- 解锁：`UPG-020`、`UPG-030`。

### RUN-040 波间恢复、复活窗口与选择流程

- 状态：Planned
- 依赖：`RUN-035`、`LIFE-030`、`UPG-010`。
- 当前缺口：波次结束后没有冻结战斗、恢复规则、倒地队友处理、强化候选和继续条件的一致阶段。
- 实施要点：进入 Intermission 后停止敌人伤害/生成；先三选一并立即应用；再按新容量补满所有武器/元素备弹和手雷；每名存活角色恢复 20% 当前最大生命；能量保留且复活物品不补；若有倒地角色则保持安全复活/跳过窗口；最后倒计时进入下一波。
- 可观察完成：波间不能被迟到攻击伤害，恢复和复活各执行一次，重复确认不重复应用强化。
- 验证：阶段事务 EditMode、迟到攻击/重入 PlayMode、人工流程。
- 解锁：`UPG-020`、`RUN-050`。

### UPG-020 强化选择 UI 与原子应用

- 状态：Planned
- 依赖：`UPG-010`、`RUN-040`、`HUD-020`。
- 当前缺口：没有从权威候选快照渲染、确认、失败回滚和历史展示的 UI 流程。
- 实施要点：UI 只展示 Run 提供的候选；确认创建唯一选择事务；应用失败不推进阶段；成功写入历史后关闭；重绑/暂停/重复点击幂等。
- 可观察完成：一次波间只能应用一个候选，UI 文本与实际效果一致，失败时可安全重试。
- 验证：ViewModel/EditMode、重复输入 PlayMode、人工可读性。
- 解锁：`UPG-030`。

### UPG-030 九个强化的代表性分批实现

- 状态：Planned
- 依赖：`UPG-020`、`WPN-060`、`ELM-100`、`SKL-060`。
- 当前缺口：设计列出的九个强化没有生产实现、组合测试或版本裁剪顺序。
- 实施要点：九项固定为精密校准、战术供弹、爆破改良、反应增幅、附着稳定、快速转化、技能回路、协同换位、强化装甲；每项唯一不叠层；每次三选一从武器/元素/战术各出一个；按共同机制小组实施并复用 Modifier/武器/元素入口；完成前三个代表闭环后再按演示期限决定内容裁剪。
- 可观察完成：每个已声明强化都能从选择 UI 生效、在 Run 历史显示、重开清除；未完成项不出现在候选池。
- 验证：单项与两两组合 EditMode/PlayMode、主线人工验收。
- 解锁：完整内容版 Run；首版可在不破坏框架的前提下裁剪到前三个代表项。

### RUN-050 成功、失败与完整重开

- 状态：Planned
- 依赖：`RUN-010`、`LIFE-020`、`RUN-040`。
- 当前缺口：没有统一终局事实、输入/敌人停机、结果快照和跨系统完整 reset。
- 实施要点：Boss/阶段完成提交 Success，全队倒地提交 Failed；只接受第一次终局；停止输入/AI/伤害/生成；结果 UI 读取快照；Restart 生成新随机种子，清理 Party、共享复活物品、弹药、技能/能量、附着、Modifier、敌人、池对象、升级和订阅后从第一波重建。
- 可观察完成：成功/失败只出现一次，连续重开多次与首次启动状态一致，无陈旧敌人、Buff 或 UI。
- 范围：跨系统高风险生命周期，建议独立审查和 Full Verified。
- 验证：reset 清单 EditMode、连续成功/失败/重开 PlayMode、Windows64 人工验收。
- 解锁：`BOS-010`、`RUN-090`。

## M12 Boss 垂直切片

### BOS-010 Boss 根、阶段与攻击调度

- 状态：Planned
- 依赖：`RUN-050`、`ENM-070`、`ELM-100`。
- 当前缺口：没有 Boss 身份、阶段状态、阶段配置、攻击调度、终局连接和完整 reset。
- 实施要点：复用 Combatant/Health/Toughness；定义 Intro/Phase1/Transition/Phase2/Defeated；阶段只调度攻击能力；Run 消费一次 Defeated；对象禁用/重开清理全部能力；配置只存不可变参数。
- 可观察完成：替身 Boss 可从进入到击败按阈值单向推进阶段，重复阈值/死亡事件不重入。
