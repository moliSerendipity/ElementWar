## M05 输入与单角色生存动作

### INP-010 活动 Input Actions 增量迁移

- 状态：Planned
- 依赖：`CMB-010`。
- 当前缺口：`InputReader` 只覆盖现有移动/瞄准/射击/装填/跳跃/技能/切换子集，Input Action 资产还包含旧 Action Map；后续闪避、双武器、角色切换、交互和投掷不能继续临时读键。
- 实施要点：① 扫描活动 Action Map、生成 C# 与场景引用；② 建立新主线动作清单和兼容映射；③ 每次只迁移一个消费者并保持旧架构只读；④ Gameplay 接收意图而非直接依赖 Input System；⑤ 输入禁用、UI 焦点和重绑生命周期统一。
- 可观察完成：新主线只有一个活动输入入口，切场景/暂停/禁用不会重复订阅或把一次输入触发两次。
- 范围：Input Action 是序列化迁移，需要引用检查与 ADR；非目标是一次删除全部旧 Map 或实现最终设置 UI。
- 验证：Action 资产静态校验、订阅生命周期 EditMode、真实输入 PlayMode、Bootstrap 人工验收。
- 解锁：`CHR-010`、`WPN-060`、`PRJ-040`、`PTY-030`、`SKL-020`、`LIFE-030`。

### CHR-010 闪避、无敌帧与动作取消

- 状态：Planned
- 依赖：`INP-010`、`CMB-010`。
- 当前缺口：没有统一闪避意图、移动执行、体力/冷却（若设计采用）、受击过滤或与射击/装填/技能的取消边界。
- 实施要点：① 固定当前移动与受击特征；② Gameplay 决定是否开始闪避；③ 移动层执行位移，伤害入口读取已提交的无敌事实；④ 明确装填、开火、技能、切角色、倒地的互斥/取消矩阵；⑤ 动画和 VFX 不写权威状态。
- 可观察完成：闪避窗口内批准类型的伤害被明确拒绝，窗口外正常命中；低帧率、连续输入和禁用不会延长无敌或卡住动作。
- 范围：角色动作/受击/表现适配；物理和计时风险高，优先独立审查。非目标是完整连招系统。
- 验证：边界时刻 EditMode/PlayMode、低帧率和多攻击压力、主线手感验收。
- 解锁：`PTY-030`、`LIFE-010`。

### HUD-010 命中、弱点、击杀、伤害数字与元素反馈

- 状态：Planned
- 依赖：`CMB-001`、`ELM-040`、`WPN-025`。
- 当前缺口：伤害事件已有消费者，但首版需要统一普通命中/弱点/击杀/反应准星与音效、步枪数字合并、爆炸/反应独立强调、敌人生命和附着图标。
- 实施要点：① 只消费已提交 Damage/Reaction/Health 事实；② 按攻击执行聚合连续步枪数字；③ 弱点、爆炸、反应和击杀使用独立优先级；④ 敌人视图显示生命/单附着，元素用颜色+图标而非只靠颜色；⑤ 对象池/禁用清理订阅与队列。
- 可观察完成：一次伤害只产生一组匹配反馈，连续步枪可读且范围/反应不被错误合并，UI 丢失不影响伤害。
- 范围：Presentation/HUD/VFX/SFX 适配；非目标是 Party、波次和 Boss HUD。
- 验证：聚合/ViewModel EditMode、生产事件 PlayMode、人工可读性和色觉区分检查。
- 解锁：`HUD-020`、`HUD-030`。

## M06 Party、第二角色与 AI 队友

### PTY-010 Party Runtime 所有权与角色槽位

- 状态：Planned
- 依赖：`ARC-010`、`WPN-040`。
- 当前缺口：没有权威 roster、活动角色、控制来源和角色运行时身份；直接做切换会让相机、HUD、AI、弹药和生命各自猜测 ActiveCharacter。
- 实施要点：① 建立 Run/场景内唯一 PartyRuntime；② 首版两个槽位持有稳定角色实例与装备/弹药引用，消费者不把上限硬编码为只能两人，以保留未来三人边界；③ 活动槽、控制来源、可切换条件和事实事件由 Party 提交；④ 场景重载、失败重开和销毁清理明确；⑤ 不用静态 `Active`/标签搜索作为第二真相源。
- 可观察完成：只有 Party 能改变活动角色，所有消费者从同一只读快照/事件观察；两个角色状态互不覆盖。
- 范围：Gameplay 状态所有权与组合根接线，需要 ADR。非目标是第二角色资产、切换动画和 AI 行为。
- 验证：状态转换 EditMode、创建/销毁/重载 PlayMode、真实 Bootstrap 引用检查。
- 解锁：`CHR-020`、`PTY-020`、`AI-010`、`SKL-010`、`ENM-020`。

### CHR-020 第二角色资产许可、导入与运行时装配

- 状态：Planned
- 依赖：`PTY-010`、`LIC-010`。
- 当前缺口：第二角色尚未完成可分发许可确认、模型/动画/Avatar/碰撞体/NavMesh 与新 C# 角色链装配。
- 实施要点：① 从已登记且许可允许的资产选择；② 保留来源、作者、版本和许可证证据；③ 在隔离 prefab 完成 Rig/Animator/Collider/角色组件；④ 运行时 ID 使用与模型解耦的 `PyroAssault` / `CryoSupport`，显示名独立；⑤ 使用 Party 槽位和当前战斗契约，不复制现有角色脚本形成第二套实现。
- 可观察完成：两个不同角色 prefab 都能单独生成、移动、受伤、装备并被 Party 识别，控制台无 Missing Script/引用。
- 范围：第三方资产、prefab 和配置迁移；需要人工视觉/动画验收。非目标是最终技能和 AI 射击。
- 验证：许可清单、GUID/引用扫描、prefab PlayMode、Bootstrap 人工验收。
- 解锁：`AI-010`、`PTY-020`。

### PTY-020 活动角色的相机、HUD 与输入绑定

- 状态：Planned
- 依赖：`PTY-010`、`CHR-020`。
- 当前缺口：相机/HUD/输入按单角色连接；切换时可能继续观察或驱动旧对象。
- 实施要点：① Party 事件触发一次原子重绑定；② Input 只驱动活动角色，AI 接管非活动角色；③ 相机在批准时点切 Follow/LookAt；④ HUD 从新角色快照重建生命、武器、弹药、元素；⑤ 旧订阅在新订阅前幂等释放。
- 可观察完成：反复切换绑定数量不增长，屏幕和控制在同一帧/批准过渡点指向同一角色，旧角色受伤不覆盖当前 HUD。
- 范围：Presentation 与输入适配，不改变 Party 权威事实。
- 验证：订阅/重绑定测试、快速切换 PlayMode、主线相机与 HUD 人工检查。
- 解锁：`PTY-030`、`HUD-020`。

### AI-010 可替换输入源与队友跟随

- 状态：Planned
- 依赖：`PTY-010`、`CHR-020`。
- 当前缺口：角色决策主要由玩家输入驱动，非活动角色没有同一意图接口、跟随目标、传送恢复或 NavMesh 失败策略。
- 实施要点：① 抽出玩家/AI 可替换意图源；② AI 只对非活动且可行动角色生效；③ 建立跟随距离、占位、卡住检测和安全追赶；④ 切换时原子交换控制来源；⑤ 禁用/倒地/场景结束停止决策。
- 可观察完成：非活动角色持续跟随且不争夺玩家控制，切换后原玩家角色立即由 AI 接管，无双重移动输入。
- 范围：角色决策接口和队友移动；不实现攻击和复杂战术。
- 验证：控制源互斥 EditMode、NavMesh/切换/卡住 PlayMode。
- 解锁：`AI-020`、`PTY-030`。

### AI-020 队友选敌、射击与资源策略

- 状态：Planned
- 依赖：`AI-010`、`WPN-060`、`ELM-040`、`ENM-020`、`MOD-010`。
- 当前缺口：AI 队友没有合法敌对目标查询、瞄准/射击节奏、视线判断，以及“不消耗弹药/元素弹/能量”的显式策略。
- 实施要点：① 复用 Combatant 阵营和目标身份；② 从威胁/距离/LOS 选敌；③ 通过同一武器意图/执行链射击；④ 用资源策略做到普通射击不耗玩家弹药、不附着、不产能量，AI 不自动施法；⑤ AI 控制期间统一 50% 承伤并与其他减伤乘算；⑥ 切换、目标死亡、队友倒地和阶段结束立即停止，玩家已释放持续技能仍保留原来源。
- 可观察完成：队友只攻击敌人、命中走同一伤害链且归属自身；玩家接管后立刻恢复玩家资源规则。
- 范围：首版简单射击 AI；非目标是完整战术树和 AI 主动使用元素弹/技能。
- 验证：选敌/资源策略 EditMode、多目标/切换 PlayMode、人工观战。
- 解锁：`RUN-010` 的完整队伍战斗。

### PTY-030 角色切换事务

- 状态：Planned
- 依赖：`PTY-020`、`AI-010`、`CHR-010`、`WPN-060`、`INP-010`。
- 当前缺口：现有配置资产冷却与设计目标存在偏差，且没有位置、朝向、速度、动作取消、碰撞占位和失败回滚的一致事务。
- 实施要点：① 启动时检查存活、1.5 秒共享冷却、场景和动作状态；② 冻结源/目标与切换代次；③ 交换位置/控制/相机，取消瞄准、普通/特殊换弹，并遵守“已生效技能与闪避不能靠切换取消”的动作矩阵；④ 已进入出手的敌人攻击继续指向交换后的战斗位置；⑤ 目标不可放置时安全失败或回滚；⑥ 修正配置资产与设计偏差。
- 可观察完成：快速连按只成功一次；两角色不会重叠穿墙或同时被玩家控制；失败切换不破坏原状态。
- 范围：Party、角色移动、输入、相机/HUD 和序列化配置；高风险，建议独立审查。非目标是倒地自动接管。
- 验证：事务状态 EditMode，物理/NavMesh/低帧率 PlayMode，主线人工验收。
- 解锁：`LIFE-010`、`SKL-020`、`HUD-020`。

## M07 倒地、接管与复活

### LIFE-010 Active / Downed / Reviving 生命周期

- 状态：Planned
- 依赖：`PTY-030`、`CHR-010`。
- 当前缺口：`HealthComponent` 只提供生命耗尽事实，没有角色倒地、复活中、重新激活或输入/受击策略。
- 实施要点：① 保持生命值唯一事实；② Party/角色生命状态机把耗尽映射为 Downed；③ 明确动作取消、碰撞、AI、受击和表现；④ Reviving 只表达事务，不直接恢复；⑤ 禁用/重开完整 reset。
- 可观察完成：生命归零恰好进入一次 Downed，倒地角色不能移动/开火/切换但仍可被批准的复活流程引用。
- 范围：新增生命阶段，不修改 `HealthComponent` 为第二状态机；状态所有权需要 ADR。
- 验证：转换/重复事件 EditMode，生产受伤/切换 PlayMode。
- 解锁：`LIFE-020`、`LIFE-030`。

### LIFE-020 自动接管与全队失败事实

- 状态：Planned
- 依赖：`LIFE-010`。
- 当前缺口：活动角色倒地后没有确定接管；全队倒地也没有 Run 可消费的唯一失败事实。
- 实施要点：① 活动角色 Downed 时选择唯一可行动队友；② 复用切换事务但绕过普通冷却；③ 无可行动角色时只提交一次 PartyDefeated；④ 阶段结束/重开取消迟到切换；⑤ Presentation 不自行打开失败界面。
- 可观察完成：一人倒地自动接管另一人；两人倒地只产生一次失败，控制权不指向无效角色。
- 验证：组合矩阵 EditMode、连续致死/同帧致死 PlayMode。
- 解锁：`RUN-050`、`LIFE-030`。

### LIFE-030 共享复活资源与交互事务

- 状态：Planned
- 依赖：`LIFE-010`、`LIFE-020`、`INP-010`。
- 当前缺口：没有共享复活次数/物品、交互范围、进度、中断、恢复量和短暂无敌的权威所有者。
- 实施要点：① Run/Party 持有共享资源；② 锁定救援者/目标和代次；③ 距离、受击、移动、阶段结束按规则中断；④ 成功时原子扣资源、恢复生命、切状态并授予短暂无敌；⑤ 重复回调和双人并发不能重复消费。
- 可观察完成：一次交互只复活一个角色并扣一次资源，中断不扣除；失败重开恢复配置初值。
- 范围：交互、Party 资源、生命和反馈；非目标是联机并发实现。
- 验证：事务/资源守恒 EditMode、真实交互 PlayMode、人工可读性检查。
- 解锁：`RUN-040`。

## M08 技能、能量、Modifier 与角色差异化

### MOD-010 Typed Modifier 与 Buff 运行时

- 状态：Planned
- 依赖：`ELM-030`、`PTY-010`。
- 当前缺口：现有 Buff/AreaEffect 多为定义壳，没有类型安全的目标属性、叠加、刷新、来源、撤销和完整 reset 消费者。
- 实施要点：① 从首批技能/反应实际需求反推最小 Modifier 类型；② 运行时保存来源、目标、层数、到期和撤销句柄；③ 不直接改 ScriptableObject；④ 同 key 规则显式；⑤ 死亡/切场景/重开/池复用无残留。
- 可观察完成：临时属性变化可精确撤销，叠加顺序确定，配置无消费者字段被拒绝或删除。
- 范围：Definition/Gameplay，可能涉及序列化迁移与 ADR；非目标是通用脚本化效果语言。
- 验证：叠加/刷新/撤销 EditMode、生命周期 PlayMode。
- 解锁：`ELM-090`、`SKL-010`、`UPG-010`。

### SKL-010 SkillDefinition / SkillRuntime 契约

- 状态：Planned
- 依赖：`PTY-010`、`MOD-010`、`ELM-030`。
- 当前缺口：现有 SkillLoadout/定义尚无稳定生产消费者，不能表达每角色技能实例、施法事务、冷却、能量、目标和效果输出。
- 实施要点：① 定义不可变技能与角色运行时实例；② 明确 CanStart/Start/Commit/Cancel/Finish；③ 输出只调用战斗、元素、Area/Modifier 公共入口；④ 切换/倒地/阶段结束取消；⑤ 配置按稳定 ID 校验。
- 可观察完成：一个无美术测试技能可经历完整事务且重复回调不重复提交。
- 范围：技能公共契约和最小替身；需要 ADR。非目标是具体四个技能内容。
- 验证：状态机/配置 EditMode、生命周期 PlayMode。
- 解锁：`SKL-020`。

### SKL-020 技能输入、冷却与能量所有权

- 状态：Planned
- 依赖：`SKL-010`、`PTY-030`、`INP-010`。
- 当前缺口：只有通用 skill 输入，没有每角色能量、普通技能/终结技资格、换人和 AI 资源策略。
- 实施要点：① 输入发 E/Q 槽位意图；② 每角色独立持有 100 能量与冷却；③ 战技每次施放至少命中一敌时获得一次 25 能量，普通射击/击杀/AI/终结技不产能量；④ 切人、波间、倒地/复活保留，技能冷却继续，新 Run 清空；⑤ AI 策略显式且不污染玩家数值。
- 可观察完成：两角色冷却/能量互不串联，资源不足时有明确拒绝原因，UI 与权威快照一致。
- 验证：资源矩阵 EditMode、切换/同帧充能 PlayMode。
- 解锁：`SKL-030`～`SKL-060`、`HUD-020`。

### SKL-030 Pyro 普通技能垂直切片

- 状态：Planned
- 依赖：`SKL-020`、`CMB-020`。
- 当前缺口：Pyro 角色没有可玩的差异化技能和真实技能到战斗/元素链证据。
- 实施要点：向准星发射 Fire 技能攻击；无论命中与否获得约 6 秒射速/换弹强化；强化武器命中按来源+目标约 1.5 秒追加 Fire；技能命中至少一敌才获得一次能量；复用伤害/附着/Modifier 并完成反馈。
- 可观察完成：技能从输入到冷却、伤害、附着、反应和反馈完整闭环。
- 验证：效果 EditMode、真实角色 PlayMode、人工手感。
- 解锁：`SKL-040`。

### SKL-040 Pyro 终结技与持续区域

- 状态：Planned
- 依赖：`SKL-030`、`PRJ-050`。
- 当前缺口：持续 AreaEffect 没有 tick 去重、进入/离开、来源快照和池复用生产证据。
- 实施要点：激活时周围 Fire 冲击；进入约 10 秒武器伤害/射速/换弹/后坐力强化和约 0.75 秒附着间隔；与战技同类强化取较强值不叠加；切为 AI 后数值强化保留但普通射击仍不附着；能量只扣一次并安全到期。
