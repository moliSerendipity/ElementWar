本路线在战斗与武器状态拥有稳定身份后再引入第二角色。Party 是角色、控制权和切换的唯一所有者；相机、HUD、AI 与表现只绑定它发布的事实，不各自保存“当前角色”。

> Planned/Ready 任务只表达目标、依赖和可观察结果；实现形状在任务成为 Next 时根据当前代码重新审计。旧实施提示由 Git 历史追溯，不保留在活动 Roadmap。

## M05 输入与单角色生存动作

### INP-010 活动 Input Actions 增量迁移
- 状态：Ready
- 依赖：`CMB-010`。
- 当前缺口：`InputReader` 只覆盖现有移动/瞄准/射击/装填/跳跃/技能/切换子集，Input Action 资产还包含旧 Action Map；后续闪避、双武器、角色切换、交互和投掷不能继续临时读键。
- 可观察完成：新主线只有一个活动输入入口，切场景/暂停/禁用不会重复订阅或把一次输入触发两次。
- 范围：Input Action 是序列化迁移，需要引用检查与 ADR；非目标是一次删除全部旧 Map 或实现最终设置 UI。
- 解锁：`CHR-010`、`WPN-060`、`PRJ-040`、`PTY-030`、`SKL-020`、`LIFE-030`。

### CHR-010 闪避、无敌帧与动作取消
- 状态：Planned
- 依赖：`INP-010`、`CMB-010`。
- 当前缺口：没有统一闪避意图、移动执行、体力/冷却（若设计采用）、受击过滤或与射击/装填/技能的取消边界。
- 可观察完成：闪避窗口内批准类型的伤害被明确拒绝，窗口外正常命中；低帧率、连续输入和禁用不会延长无敌或卡住动作。
- 范围：角色动作/受击/表现适配；验证按实际物理与计时行为选择。非目标是完整连招系统。
- 解锁：`PTY-030`、`LIFE-010`。

### HUD-010 命中、弱点、击杀、伤害数字与元素反馈
- 状态：Planned
- 依赖：`CMB-001`、`ELM-040`、`WPN-025`。
- 当前缺口：伤害事件已有消费者，但首版需要统一普通命中/弱点/击杀/反应准星与音效、步枪数字合并、爆炸/反应独立强调、敌人生命和附着图标。
- 可观察完成：一次伤害只产生一组匹配反馈，连续步枪可读且范围/反应不被错误合并，UI 丢失不影响伤害。
- 范围：Presentation/HUD/VFX/SFX 适配；非目标是 Party、波次和 Boss HUD。
- 解锁：`HUD-020`、`HUD-030`。

### PTY-010 Party Runtime 所有权与角色槽位
- 状态：Planned
- 依赖：`ARC-010`、`WPN-040`。
- 当前缺口：没有权威 roster、活动角色、控制来源和角色运行时身份；直接做切换会让相机、HUD、AI、弹药和生命各自猜测 ActiveCharacter。
- 可观察完成：只有 Party 能改变活动角色，所有消费者从同一只读快照/事件观察；两个角色状态互不覆盖。
- 范围：Gameplay 状态所有权与组合根接线；若实际改变长期状态所有权则升级 Full 并评估 ADR。非目标是第二角色资产、切换动画和 AI 行为。
- 解锁：`CHR-020`、`PTY-020`、`AI-010`、`SKL-010`、`ENM-020`。

### CHR-020 第二角色资产许可、导入与运行时装配
- 状态：Planned
- 依赖：`PTY-010`、`LIC-010`。
- 当前缺口：第二角色尚未完成可分发许可确认、模型/动画/Avatar/碰撞体/NavMesh 与新 C# 角色链装配。
- 可观察完成：两个不同角色 prefab 都能单独生成、移动、受伤、装备并被 Party 识别，控制台无 Missing Script/引用。
- 范围：第三方资产、prefab 和配置迁移；需要人工视觉/动画验收。非目标是最终技能和 AI 射击。
- 解锁：`AI-010`、`PTY-020`。

### PTY-020 活动角色的相机、HUD 与输入绑定
- 状态：Planned
- 依赖：`PTY-010`、`CHR-020`。
- 当前缺口：相机/HUD/输入按单角色连接；切换时可能继续观察或驱动旧对象。
- 可观察完成：反复切换绑定数量不增长，屏幕和控制在同一帧/批准过渡点指向同一角色，旧角色受伤不覆盖当前 HUD。
- 范围：Presentation 与输入适配，不改变 Party 权威事实。
- 解锁：`PTY-030`、`HUD-020`。

### AI-010 可替换输入源与队友跟随
- 状态：Planned
- 依赖：`PTY-010`、`CHR-020`。
- 当前缺口：角色决策主要由玩家输入驱动，非活动角色没有同一意图接口、跟随目标、传送恢复或 NavMesh 失败策略。
- 可观察完成：非活动角色持续跟随且不争夺玩家控制，切换后原玩家角色立即由 AI 接管，无双重移动输入。
- 范围：角色决策接口和队友移动；不实现攻击和复杂战术。
- 解锁：`AI-020`、`PTY-030`。

### AI-020 队友选敌、射击与资源策略
- 状态：Planned
- 依赖：`AI-010`、`WPN-060`、`ELM-040`、`ENM-020`、`MOD-010`。
- 当前缺口：AI 队友没有合法敌对目标查询、瞄准/射击节奏、视线判断，以及“不消耗弹药/元素弹/能量”的显式策略。
- 可观察完成：队友只攻击敌人、命中走同一伤害链且归属自身；玩家接管后立刻恢复玩家资源规则。
- 范围：首版简单射击 AI；非目标是完整战术树和 AI 主动使用元素弹/技能。
- 解锁：`RUN-010` 的完整队伍战斗。

### PTY-030 角色切换事务
- 状态：Planned
- 依赖：`PTY-020`、`AI-010`、`CHR-010`、`WPN-060`、`INP-010`。
- 当前缺口：现有配置资产冷却与设计目标存在偏差，且没有位置、朝向、速度、动作取消、碰撞占位和失败回滚的一致事务。
- 可观察完成：快速连按只成功一次；两角色不会重叠穿墙或同时被玩家控制；失败切换不破坏原状态。
- 范围：Party、角色移动、输入、相机/HUD 和必要配置；验证与审查等级在任务成为 Next 后按实际改动决定。非目标是倒地自动接管。
- 解锁：`LIFE-010`、`SKL-020`、`HUD-020`。

### LIFE-010 Active / Downed / Reviving 生命周期
- 状态：Planned
- 依赖：`PTY-030`、`CHR-010`。
- 当前缺口：`HealthComponent` 只提供生命耗尽事实，没有角色倒地、复活中、重新激活或输入/受击策略。
- 可观察完成：生命归零恰好进入一次 Downed，倒地角色不能移动/开火/切换但仍可被批准的复活流程引用。
- 范围：新增生命阶段，不修改 `HealthComponent` 为第二状态机；若实际改变长期状态所有权则升级 Full 并评估 ADR。
- 解锁：`LIFE-020`、`LIFE-030`。

### LIFE-020 自动接管与全队失败事实
- 状态：Planned
- 依赖：`LIFE-010`。
- 当前缺口：活动角色倒地后没有确定接管；全队倒地也没有 Run 可消费的唯一失败事实。
- 可观察完成：一人倒地自动接管另一人；两人倒地只产生一次失败，控制权不指向无效角色。
- 解锁：`RUN-050`、`LIFE-030`。

### LIFE-030 共享复活资源与交互事务
- 状态：Planned
- 依赖：`LIFE-010`、`LIFE-020`、`INP-010`。
- 当前缺口：没有共享复活次数/物品、交互范围、进度、中断、恢复量和短暂无敌的权威所有者。
- 可观察完成：一次交互只复活一个角色并扣一次资源，中断不扣除；失败重开恢复配置初值。
- 范围：交互、Party 资源、生命和反馈；非目标是联机并发实现。
- 解锁：`RUN-040`。

### MOD-010 Typed Modifier 与 Buff 运行时
- 状态：Planned
- 依赖：`ELM-030`、`PTY-010`。
- 当前缺口：现有 Buff/AreaEffect 多为定义壳，没有类型安全的目标属性、叠加、刷新、来源、撤销和完整 reset 消费者。
- 可观察完成：临时属性变化可精确撤销，叠加顺序确定，配置无消费者字段被拒绝或删除。
- 范围：Definition/Gameplay，可能涉及序列化迁移与 ADR；非目标是通用脚本化效果语言。
- 解锁：`ELM-090`、`SKL-010`、`UPG-010`。

### SKL-010 SkillDefinition / SkillRuntime 契约
- 状态：Planned
- 依赖：`PTY-010`、`MOD-010`、`ELM-030`。
- 当前缺口：现有 SkillLoadout/定义尚无稳定生产消费者，不能表达每角色技能实例、施法事务、冷却、能量、目标和效果输出。
- 可观察完成：一个无美术测试技能可经历完整事务且重复回调不重复提交。
- 范围：技能最小公共契约和测试替身；只有形成长期跨模块契约时才升级 Full 并评估 ADR。非目标是具体四个技能内容。
- 解锁：`SKL-020`。

### SKL-020 技能输入、冷却与能量所有权
- 状态：Planned
- 依赖：`SKL-010`、`PTY-030`、`INP-010`。
- 当前缺口：只有通用 skill 输入，没有每角色能量、普通技能/终结技资格、换人和 AI 资源策略。
- 可观察完成：两角色冷却/能量互不串联，资源不足时有明确拒绝原因，UI 与权威快照一致。
- 解锁：`SKL-030`～`SKL-060`、`HUD-020`。

### SKL-030 Pyro 普通技能垂直切片
- 状态：Planned
- 依赖：`SKL-020`、`CMB-020`。
- 当前缺口：Pyro 角色没有可玩的差异化技能和真实技能到战斗/元素链证据。
- 可观察完成：技能从输入到冷却、伤害、附着、反应和反馈完整闭环。
- 解锁：`SKL-040`。

### SKL-040 Pyro 终结技与持续区域
- 状态：Planned
- 依赖：`SKL-030`、`PRJ-050`。
- 当前缺口：持续 AreaEffect 没有 tick 去重、进入/离开、来源快照和池复用生产证据。
- 可观察完成：区域持续作用且每目标频率正确，换角色后归因不变，复用无旧状态。
- 解锁：完整 Pyro 角色切片。

### SKL-050 Cryo 普通技能垂直切片
- 状态：Planned
- 依赖：`SKL-020`、`ELM-050`、`ELM-080`。
- 当前缺口：Cryo 角色没有真实 Ice 来源和冻结联动。
- 可观察完成：技能可稳定施加 Ice 并按目标类型产生冻结或批准替代结果。
- 解锁：`SKL-060`。

### SKL-060 Cryo 终结技、区域与霜甲
- 状态：Planned
- 依赖：`SKL-050`、`MOD-010`、`PRJ-050`。
- 当前缺口：没有持续区域叠加与角色防护 Modifier 的组合生命周期。
- 可观察完成：区域与霜甲按配置开始/结束，换人、倒地、重开不残留，HUD 可读。
- 解锁：完整 Cryo 角色切片。

### HUD-020 Party、技能与状态 HUD 收口
- 状态：Planned
- 依赖：`HUD-010`、`PTY-020`、`LIFE-030`、`SKL-020`、`WPN-060`。
- 当前缺口：生命、弹药、元素、技能、倒地/复活和切换冷却尚未由统一只读快照驱动。
- 可观察完成：所有核心状态可读且切换一致，UI 禁用再启用不会重复或显示陈旧数据。
- 解锁：`RUN-010` 的完整战斗 HUD、`HUD-030`。
