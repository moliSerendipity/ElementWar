# ElementWar 功能工作流与完成标准

本文件是大型任务流程、文档职责、验证等级和完成标准的唯一维护来源；`AGENTS.md` 保存硬边界，项目 Skill 只负责按需加载和执行路由。

## 1. 权威来源与短指令

| 内容 | 权威来源 |
|---|---|
| 当前架构、状态所有权、主线/旧架构边界 | [`Architecture.md`](Architecture.md) |
| 目标玩法 | [`GameDesign.md`](GameDesign.md) 及相关 Design 细则 |
| 开发顺序、依赖、状态和唯一 `Next` | [`DevelopmentRoadmap.md`](DevelopmentRoadmap.md) 及路线细则 |
| 一次获批切片与最终证据 | 适用的 Feature Spec / ADR |
| 流程、文档维护、证据等级和完成标准 | 本文件 |

- `继续下一阶段`：读取唯一 `Next`、对应路线细则和实时仓库后进入只读检查。
- `开始功能：<名称或 ID>`：核对指定任务和依赖，不静默跳过前置条件。
- `按已批准 Feature Spec 继续实施`：仅在契约已批准且实时范围没有高影响漂移时恢复。

短指令不批准未知方案。没有或存在多个 `Next`、依赖缺失、权威来源冲突时必须暂停。

## 2. 只读检查、契约与授权

大型任务先检查相关实现、调用链、asmdef、配置/序列化引用、测试入口、文档和 Git 状态。仓库能确认的事实不询问；只集中询问会改变范围、行为、接口、状态所有权、技术取舍或验收的问题。

授权前在对话中总结可观察目标、非目标、允许/禁止范围、方案、风险、假设和验收，不编辑文件或创建正式 Feature Spec。获得“开始实施”“按此执行”或同等授权后，才按 [`Features/TEMPLATE.md`](Features/TEMPLATE.md) 创建或更新适用的 Spec；用户明确不需要时不新增。

任务组织按风险选择：局部闭环可在同一任务完成；跨系统但边界明确时使用一个垂直切片；公共契约、状态所有权、序列化、物理/计时、迁移或发布风险需要独立设计门和更强审查；未知缺陷先做有上限的只读审计、特征测试或隔离原型。不要为省对话固定合并，也不要为流程形式固定拆分。

## 3. 最小实现与稳定接缝

批准方案必须比较“当前最小实现”和“最低成本稳定接缝”。新增生产脚本、类型、公共接口、字段、配置资产、缓存或状态时，逐项说明：

1. 当前验收直接需要的职责，或已批准后续行为的具体依据。
2. 推迟是否会造成明确的 API 破坏、序列化迁移、状态迁移或重复实现。
3. 当前方案为什么是最小稳定接缝，以及更小方案具体不足在哪里。

可以保留当前职责，以及已批准需求确实需要、延后成本明确且当前形状最小的接缝。消费者尚未实施不能单独否定它；Roadmap 中存在未来任务或“以后可能用”也不能单独证明它。没有具体行为和延后成本、却引入未使用包装、分支、资产、缓存、状态或重复校验的复杂度必须移除。

配置结构、请求输入和可变运行时状态分别只有一个不变量所有者。启动期已验证的配置不在 Gameplay 热路径重复完整校验；跨层防御必须对应上游之后可能发生的真实失败。结果只携带调用方无法从输入或权威状态恢复的事实。

## 4. 实施与文档维护

- 一次实现一个完整、可观察、可验证的行为链；复用权威状态和已发生事实，不顺手清理旧架构或无关代码。
- 处理适用的初始化、启用/禁用、订阅/退订、死亡、重置和对象池复用。超出获批范围或复杂度边界时暂停并重新授权；每个切片后检查 scoped diff。
- 文档只保留当前事实、契约、运行方式、最终证据和维护约束。最终状态删除实施时间线、被替代方案、重复授权以及可由 Git/日志恢复的过程；必须保留的历史压缩为一条结论和证据路径。
- 同一事实只在一个权威来源展开，其他位置链接引用；修改时同步受影响的导航和摘要，不复制正文，不填充无信息模板章节。
- 长期文档超过 300 个非空行，或同时承载多个通常独立读取的子系统时，按稳定职责拆分；总览只保留导航和跨域约束。设计资料先由总览定位，再按需加载。
- 路线始终只有一个 `Next`。收口时更新任务状态、证据和解锁项；设计文档描述目标行为，Feature Spec 描述获批切片，路线只维护顺序与状态。

## 5. 验证、审查与完成声明

| 等级 | 必需证据 | 可声明含义 |
|---|---|---|
| Implemented | 代码与 scoped diff | 已实现，尚未验证完成 |
| Fast Verified | 精确测试 + EditMode | 当前切片验证通过 |
| Full Verified | EditMode + PlayMode + Windows64 | 可进入人工验收 |
| Accepted | Full 证据 + 主线人工验收 + 文档闭环 | 功能完成 |

测试命令返回 0 项、缺失目标 XML/Player、非零退出码或使用早于当前源码的证据都视为失败；不适用层级省略，跳过项写“未运行”。具体选择和当前命令只在需要验证时读取 Skill 的 `references/verification-matrix.md`。

独立只读审查按风险决定：公共接口/状态所有权/程序集、序列化迁移、物理/计时/异步/对象池、高扩散事件、发布候选、大型 diff 或大量反射/替身测试优先独立审查；局部且直接自动化覆盖的差异可同任务自审。发现分类如下：

| 分类 | 处理 |
|---|---|
| 已确认缺陷 / 违反验收 | 阻断；在授权范围内修复并重验，或重新批准契约 |
| 证据缺口 | 补证据或下调完成等级，不自动证明代码有缺陷 |
| 可选增强 | 进入路线或后续任务，不扩大当前范围 |

收口必须满足：获批契约与 scoped diff 一致；必要性/扩展性、所有权、生命周期和序列化影响已审查；适用验证达到本切片目标等级，若执行测试则数量必须大于 0；性能声明有代表性 Player 数据；Feature Spec/ADR 和路线（如适用）已同步。最终报告列出实际行为与文件、命令、数量和结果、证据路径、人工验收、未运行项、风险与回滚。仅“代码已写”或“编译通过”不算完成。
