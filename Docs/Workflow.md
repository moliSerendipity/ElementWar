# ElementWar Full Workflow

本文件只用于 Full 任务。Fast / Standard 的路由、授权和上下文预算由根 `AGENTS.md` 与项目 Skill 负责。

## 1. 进入条件

出现以下任一项才进入 Full：

- 权威状态所有者或跨模块公共契约变化；
- asmdef / 层级依赖方向变化；
- scene、prefab、ScriptableObject、Input Action 等序列化迁移；
- Legacy 与新主线的迁移/收敛；
- 发布级性能、兼容性或构建风险；
- 多个合理方案会实质改变玩法、接口、迁移或可观察验收；
- 缺陷影响范围未知且可能跨上述边界。

新功能、跨文件修改或文件数量多，本身不构成 Full。

## 2. Full 契约

先建立当前事实，只读取与选择直接相关的实现、消费者、测试和架构页。仓库能回答的内容不询问。

在需要用户选择前，只总结：

- 可观察目标 / 非目标；
- 允许修改和明确禁止范围；
- 当前事实与未决选择；
- 推荐方案及一个真正可行的替代方案（存在时）；
- 会改变行为/接口/迁移的风险；
- 可观察验收。

用户已经明确要求实现时，不重复请求对“显然的最小细节”授权；只对尚未决定的高影响选择确认。确认后只有在需要长期契约、迁移记录或复杂验收边界时才创建/更新 Feature Spec；否则直接实施。

## 3. 简单优先与防御边界

当前需求是复杂度上限的主要依据。新增非平凡类型、状态、缓存、包装层或校验时，只需回答：

1. 哪个当前行为/消费者需要它？
2. 如果删掉，当前合法路径会出现什么具体问题？
3. 若理由来自迁移，为什么现在不做会产生确定的 API/序列化破坏或重复实现？

三项都没有明确依据时，不新增。

不为当前调用链不存在的故障模式或未来扩展增加代码。只有仓库存在对应路径，或本任务明确引入该路径时才处理。已由单一上游边界保证的不变量，不在 Gameplay 热路径重复完整校验。

## 4. 实施

- 一次完成一个完整、可观察、可验证的垂直切片。
- 复用现有事实源，不增加第二套状态；不顺手重构无关旧代码。
- 只处理当前真实生命周期，以仓库实际调用路径为准，不套固定检查表。
- 出现新的 Full 级选择时暂停；普通实现细节不反复请求授权。
- 每个切片后检查 scoped diff。

## 5. 文档规则

文档优先服务“当前决策”和“快速定位”，不是保存完整实施过程。

- **Rule / Current** 放正文前部，使用短句、表格或明确条目。
- **Rationale** 只解释代码/规则本身无法表达的长期原因。
- **History** 只保留仍会影响未来决策的结论；过程、被替代方案、重复授权、聊天记录和可由 Git 恢复的时间线删除。
- 同一事实只在一个权威来源展开，其他位置只链接。
- Closed Feature Spec 压缩为最终契约、关键文件/契约、证据、剩余边界和 ADR 链接。
- ADR 只记录长期决策、主要替代方案、后果和重新评估条件，不复制 Feature 验收或完整测试日志。

## 6. 验证等级

| 等级          | 最低证据                               | 可声明含义             |
| ------------- | -------------------------------------- | ---------------------- |
| Implemented   | 代码 + scoped diff                     | 已实现，未完成运行验证 |
| Fast Verified | 当前切片精确测试 + EditMode（适用时）  | 当前切片验证通过       |
| Full Verified | 适用的 EditMode + PlayMode + Windows64 | 可进入人工验收         |
| Accepted      | Full 证据 + 主线人工验收 + 文档闭环    | 功能完成               |

0 项测试、缺失目标证据、非零退出码或早于当前源码的证据都不是通过。不适用层级省略，未运行项写“未运行”。

## 7. 收口

收口只记录：实际行为/文件、执行过的命令与结果、证据路径、未运行项、真实剩余风险和回滚单位。路线任务同步状态、证据、解锁项和唯一 `Next`；不要把可选增强带入当前范围。
