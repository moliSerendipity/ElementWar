# 单机边界与未来联机实验

- 状态：首版边界已确认，实验细节待单机垂直切片后定义
- 维护日期：2026-08-07

本文是正式试玩版与未来网络实验之间的设计边界。它不批准当前接入网络代码，也不代表现有网络包已经参与运行时。

## 已确认方向

- 2026-09-10 的公开试玩版以单机完成度为优先，联机不是发布必需条件。
- 先完成可独立游玩的单机垂直切片，再安排一个有明确时间上限的网络战斗实验。
- 实验目标为两人 PvE，采用主机权威模式。
- 单机模式保留角色切换；双人模式中每名玩家控制一个固定角色，不在战斗中交换控制权。
- 网络实验与正式试玩版分开验收；实验延期或失败不能阻止单机版本交付。

## 当前开发需要保留的边界

- 输入表达玩家意图，伤害、生命、共享复活道具、元素附着、反应、倒地、复活和波次进度由 Gameplay 权威状态提交，Presentation 只响应已经发生的事实。
- 配置定义与可变运行时状态分离；角色、武器、技能、投射物、强化和元素来源使用稳定定义标识与运行时实例标识。
- 随机波次和三选一使用可保存的局内种子，不把随机结果只存在表现层。
- 枪械命中、爆炸、技能和反应应先形成明确的执行请求与结果事实，避免 UI、动画或特效直接修改生命和元素状态。
- 投射物与爆炸物在生成时固定来源角色，以及由玩家输入还是 AI 自主发起；后续切人或控制权变化不得改写该事实。
- 当前不为“以后可能联网”提前复制一套网络状态、网络事件或网络专用角色实现。
- 只有网络实验开始后，才根据实际同步边界增加网络适配层。

这些约束同时服务单机可测试性，不要求首版承担完整联网复杂度。

## 主机权威原则

- 主机最终裁决角色状态、有效命中、伤害、生命、共享复活道具数量与消耗、元素附着、反应、倒地、复活、敌人状态、波次进度和强化结果。
- 客户端发送输入或行为请求，并可以提供必要的本地表现预测；不能自行确认伤害和反应事实。
- 远程表现只消费同步后的事实，不重复运行另一套结果裁决。
- 具体射击判定补偿、投射物同步频率和延迟容忍目标在实验 Feature Spec 中决定。

## 网络实验启动条件

- 单机三波流程可以完整开始、成功、失败和重开。
- 两名角色的移动、射击、切换、技能、倒地和复活在单机中稳定。
- 四元素、六反应和 Boss 特殊规则已经通过最小自动化与人工验收。
- 伤害、元素和波次状态具有明确唯一所有者，不依赖旧 Lua 主链或表现层写回。
- Windows64 单机版本已有可重复构建和运行证据。

## 实验范围待确认

开始网络实验前另建 Feature Spec，至少重新确认：

- 两名玩家的连接、生成、所有权和断线处理。
- 是否保留 AI 补位，以及一名玩家倒地后的控制规则。
- Hitscan、榴弹投射物、技能、元素反应和 Boss AI 中哪些进入首轮同步范围。
- 是否需要延迟补偿、客户端预测和回滚，及其可接受误差。
- 主机离开、重新连接和进度保存是否明确排除。
- 实验成功需要展示的录像、日志、双客户端测试和性能证据。

## 明确非目标

- 截止日期前把主游戏全面改造成联网架构。
- 公网匹配、大厅、账号、专用服务器、主机迁移和反作弊。
- 跨平台联机、在线存档、长期服务端运维和商业化后台。
- 在网络实验前修改单机设计，只为适配尚未验证的网络假设。
