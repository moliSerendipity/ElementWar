# 元素与反应设计

- 状态：首版规则与初始调试值已确认
- 维护日期：2026-08-23

本文是元素附着、反应结果、控制处理和未来扩展边界的设计事实源。武器弹药与技能来源见 [`Combat.md`](Combat.md)，反应在波次和 Boss 中的使用见 [`Run.md`](Run.md)。本文描述目标行为，不代表旧 Lua 或新 C# 主线已经完成收敛。

## 当前实现边界

- 新 C# 伤害主线已经用 `ElementType.None/Fire/Water/Electric/Ice` 建立正式伤害元素语义，并与 `DamageDeliveryType.Direct/Explosion` 分离；伤害元素轴仍只选择抗性，不会隐式产生附着。
- 新 C# 主线已有独立 `ElementApplicationProfileConfig → ElementApplicationSourceSnapshot → ElementApplicationRequest → ElementReactionPipeline → ElementAttachmentRuntime` 链路。不可变来源快照由多个小型请求共享；请求保存执行和目标身份；管线提供单请求及固定弹药先、技能后的双请求入口，低层 Resolver 不作为生产公共入口；Bootstrap 两处敌方根拥有实际附着消费者。
- 元素请求与伤害请求并列，不读取 `DamageResult`；零伤害、伤害免疫或纯施加技能可以独立尝试附着。目标运行时只把当前 `HealthComponent` 作为接收资格与死亡/重置生命周期事实，不写入第二套生命或伤害状态。
- `ConfigId` 只标识规则。每个目标附着运行时在自己的 TargetId 生命周期内按 `ElementApplicationSourceId` 持有来源间隔，不复制组合键。首版主要槽支持同元素以最近合法来源刷新和显式到期；异元素由反应管线按固定无序元素对映射，并在目标侧原子登记触发来源间隔/执行去重、消费版本匹配的已有附着。
- 附着事实变化通过 `ElementAttachmentChangedEvent` 发布；成功反应结果由调用管线的未来 Gameplay 生产者直接接收，本阶段不发布无消费者的反应事件。开发调试 Presenter 只读维护当前目标列表，不参与 Gameplay 裁决。现行实现契约见 [`ADR-Element-Pipeline-Simplification-v1.md`](../Decisions/ADR-Element-Pipeline-Simplification-v1.md)。
- 默认 Registry 只登记步枪火弹/雷弹 Profile，初值均为 `0` 秒来源间隔和 `6` 秒持续时间。火、水、雷、冰六个组合是首版固定 Gameplay 映射，不维护反应表资产。真实武器来源仍由 `WPN-010` 接入，具体反应输出由后续 `ELM-040` / `ELM-060`～`ELM-090` 负责。

## 首版元素集合

- 火、水、雷、冰四种元素，两两组合形成六种反应。
- 枪械只允许装填其配置支持的元素，具体映射以 [`Combat.md`](Combat.md) 为准。
- 角色拥有固定元素，角色技能可以与当前枪械弹药共同制造反应。
- AI 普通射击不附着元素；玩家已经释放的持续技能仍可继续附着元素。
- 首版敌人不向角色附着元素，角色不会成为元素反应目标。

## 附着与触发

- 首版敌人同时只维护一个主要元素附着，默认持续 `6` 秒。
- 无附着时写入本次元素；相同元素再次附着时只刷新持续时间。
- 不同元素命中已有附着时触发对应反应；已有附着和触发元素均被完全消耗，反应后不留下新附着。
- 元素先后顺序不改变反应种类和首版核心结果，但运行时必须保留已有附着、触发元素及其来源顺序。
- 每个攻击事件对同一目标最多触发一次反应；触发后，该事件剩余的元素应用不再处理，也不能留下附着。
- 枪械、战技、终结技和持续区域分别使用自己的元素应用配置。应用间隔按“来源 + 目标”独立计算，不设置全局反应冷却。
- 范围攻击对范围内每个目标独立判定附着和反应，但同一攻击事件在单个目标上仍受一次反应限制。
- 反应生成的伤害、控制和范围效果不附着元素，也不会递归触发新反应。

## 同一命中的顺序与归属

- 同一命中包含多个元素应用时，先处理弹药元素，再处理技能附加的火元素；一旦触发反应便停止该目标的后续元素处理。
- 反应责任归属于第二个元素的施加者，即反应触发者；伤害归属、击杀归属和反馈来源均使用该责任角色。
- 已释放的持续技能在切换角色后仍保留原施放者作为来源；由它施加第二个元素时，反应归属于原施放者。

## 通用计算规则

- 蒸发和融化直接修改触发命中的伤害结果，继承该命中的攻击者增益和弱点判定，再按正常流程经过目标减伤。
- 独立反应伤害以“触发基准伤害”为基础：包含攻击者侧增益，但不包含弱点倍率和目标减伤；计算反应系数后再经过目标减伤。
- 独立反应伤害不能暴击、不能命中弱点、不附着元素、不继续触发反应，也不会伤害玩家或 AI 队友。
- Boss 可以正常获得附着并触发六种反应，没有首版元素免疫；无法接受的位移或硬控制按各反应规则转换为韧性效果。
- 多个减速同时存在时不叠加，采用幅度最强者并刷新其持续时间。

下文均为首版初始调试值，不是最终平衡承诺。

## 六种反应

### 蒸发：火 + 水

- 本次触发命中的伤害倍率为 `1.50`。
- 只影响触发命中的单个目标，不生成额外范围伤害。

### 融化：火 + 冰

- 本次触发命中的伤害倍率为 `1.35`。
- 本次触发命中的韧性伤害倍率为 `1.50`。

### 超载：火 + 雷

- 产生一次独立范围伤害，伤害为触发基准伤害的 `80%`，半径 `3.5` 米。
- 普通敌人受到短距离水平推动和强硬直，但不会被击飞到空中。
- 精英敌人不发生位移，只承受硬直和韧性伤害。
- Boss 仍承受反应伤害，但控制效果只转换为韧性伤害。
- 超载不伤害玩家或 AI 队友，也不受“爆破改良”强化。

### 感电：水 + 雷

- 主要目标承受触发基准伤害 `50%` 的独立反应伤害。
- 从主要目标周围 `6` 米内，选择最多 `2` 个距离最近且有视线的其他敌人；每个次要目标承受触发基准伤害的 `35%`。
- 同一次感电不能重复命中同一目标，次要目标不会继续向外传递，也不会获得元素附着。

### 冻结：水 + 冰

- 不产生额外反应伤害。
- 普通敌人硬控制 `2` 秒，精英敌人硬控制 `1` 秒。
- 受到伤害不会提前解除冻结；首版没有碎冰，也不额外设置冻结后的免疫或抗性时间。
- 冻结结束后必须重新施加水、冰组合才能再次冻结。
- Boss 不受硬控制，改为减速 `25%`、持续 `2` 秒，并使本次触发命中的韧性伤害倍率变为 `1.50`。

### 超导：雷 + 冰

- 超导只施加状态，不产生额外反应伤害。
- 普通和精英敌人减速 `25%`，并使其受到的非反应伤害提高 `15%`，持续 `5` 秒。
- Boss 的减速降低为 `10%`，但保留完整的 `15%` 非反应伤害易伤。
- 超导的减速和易伤不叠层，只采用最强效果并刷新持续时间；易伤不反向放大反应伤害。

## 反应增幅

- “反应增幅”提供独立的 `1.25` 乘算倍率，原始反应倍率和伤害系数保持不变。
- 最终反应数值按 `基础反应数值 × 反应增幅倍率` 计算；未获得强化时，反应增幅倍率为 `1.00`。
- 蒸发强化后为 `1.50 × 1.25 = 1.875`；融化伤害强化后为 `1.35 × 1.25 = 1.6875`。
- 超载和感电的独立反应伤害乘 `1.25`；反应产生的韧性伤害、失衡或削韧强度同样乘 `1.25`。
- 反应增幅不改变作用半径、目标数量、位移距离、减速、易伤和控制持续时间。

## 首版明确不做

- 完整元素量、残留量和衰减量计算。
- 强元素、弱元素和不同附着单位。
- 元素精通及其完整成长公式。
- 复杂 ICD 组、命中计数规则和跨技能共享 ICD。
- 多个同时存在的主要元素附着。
- 碎冰、反应产物附着元素或递归触发元素反应。

## 后续扩展边界

- 元素应用使用独立 Application Profile 表达元素、来源—目标间隔和持续时间，而不是把规则硬编码到枪械或技能中；首版不在 Profile 中加入强弱元素或复杂 ICD。
- 运行时附着容器首版只暴露一个主要槽位；出现真实多附着需求时再重新设计集合契约。
- 反应计算通过独立服务处理输入元素、目标状态和输出事实，表现层不裁决反应。
- 定义数据与运行时状态分离，使新增元素、反应和网络同步不要求替换现有伤害事实源。
- 即使首版结果与顺序无关，也保留附着方、触发方、技能/武器来源和责任角色信息。
